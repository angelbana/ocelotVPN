# Запуск программы

[![EN](https://img.shields.io/badge/lang-EN-6c757d?style=flat-square)](running.md)
[![RU](https://img.shields.io/badge/lang-RU-0b5fff?style=flat-square)](running.ru.md)

Ocelot собирается для Windows и для Linux, и каждая поставка публикуется как
артефакт прогона рабочего процесса выпуска. Обе несут всё нужное с собой, кроме
системных библиотек, названных ниже.

Для macOS есть отдельный клиент:
[ocelotVPN](https://github.com/mraliscoder/ocelotVPN). Этот проект его не
собирает.

Артефакты прогона перечислены внизу его страницы в разделе
`Actions -> Release -> <прогон>`, либо доступны через GitHub CLI:

    gh run download <номер-прогона> -R angelbana/ocelotVPN-windows -n windows-installer

| Артефакт            | Содержимое                                      | Подпись |
|---------------------|-------------------------------------------------|---------|
| `windows-installer` | установщик и его контрольная сумма SHA-512      | да      |
| `linux-appimage`    | образ приложения и его сумма SHA-512            | нет     |

Если файл передавали вне прогона, сверьте его с соседним файлом `.sha512`.


## Windows

Скачайте `windows-installer`, распакуйте архив и запустите установщик.

Установщик и программа внутри него подписаны по Authenticode и снабжены
меткой времени, поэтому Windows называет издателя, а не предупреждает о
неизвестном. Проверить до установки:

    Get-AuthenticodeSignature .\ocelot-<версия>-win64.exe

Программе нужны права администратора, и она запрашивает их при каждом запуске:
без них невозможно создать адаптер Wintun, и соединение обрывается сразу после
согласования туннеля. Так и задумано — это не лишнее окно, которое следует
закрыть.

Всё необходимое устанавливается вместе с ней: среда Qt, библиотеки
openconnect, `wintun.dll` и `vpnc-script.js`.


## Linux

Скачайте `linux-appimage`, сделайте файл исполняемым и запустите:

    chmod +x ocelot-x86_64.AppImage
    sudo ./ocelot-x86_64.AppImage

Права суперпользователя нужны для устройства tun; сама программа их не
повышает, поэтому запускать её надо уже с ними.

Образ приложения несёт внутри Qt, его модули QML, библиотеку openconnect и
GnuTLS, поэтому ставить пакеты ради них не требуется. От дистрибутива он ждёт
лишь графический и шрифтовой набор, который есть на любом рабочем столе, —
внутрь их намеренно не кладут, так как они привязаны к драйверам самой машины:

    libGLX.so.0  libOpenGL.so.0  libEGL.so.1  libX11.so.6
    libfontconfig.so.1  libfreetype.so.6  libharfbuzz.so.0

Ещё нужен `/etc/vpnc/vpnc-script` — в большинстве дистрибутивов он приходит с
пакетом `vpnc-scripts`.

Своей области уведомлений у GNOME нет, поэтому значок и всплывающее окно там не
появляются, пока их не даст расширение. Программа пишет об этом в журнал и
работает дальше: всё нужное есть в окне.

### Где он запускался

Образ приложения был запущен на **Ubuntu 24.04** и продолжал работать. В этом
и весь смысл: в Ubuntu 24.04 идёт Qt 6.4, а программа собрана с более новой Qt
на Fedora, и голая сборка там не стартует вовсе —

    libQt6Core.so.6: version `Qt_6.8' not found

У образа приложения такой беды нет: та Qt, с которой он собран, путешествует
вместе с ним.

Подключение таким способом не проверялось — ему нужны права суперпользователя
и устройство tun, — поэтому первое настоящее подключение считайте проверкой.


## Откуда берётся версия

Версия в имени файла получается из `git describe --tags`, то есть следует
тегу, от которого запущен прогон. Имя не повторяет тег буквально: ведущая `v`
отбрасывается, а дефис становится точкой — тег `v1.0.0` даёт
`ocelot-1.0.0-oc-9.12-win64.exe`.

Прогон, запущенный от ветки, а не от тега, несёт вместо этого описание
коммита, а дерево, которое git считает изменённым, добавляет суффикс `dirty`.
